Strandedness

Telling bramble which strand short reads come from.

By default, bramble checks a short read against transcripts on both strands. If the reads come from a stranded library, you can tell bramble which strand each read is on, so it only considers transcripts on that strand. The flags mean the same as in StringTie and HISAT2:

LibrarybrambleHISAT2 --rna-strandnessStringTiesalmon library type
fr-firststrand, e.g. dUTP--rfRF (single-end R)--rfISR (single-end SR)
fr-secondstrand--frFR (single-end F)--frISF (single-end SF)
unstrandedneitherdefaultdefaultIU (single-end U)

--rf

The library is fr-firststrand, as in dUTP protocols: read 1 (or a single-end read) is the reverse complement of the transcript, and read 2 has the transcript's sequence.

--fr

The library is fr-secondstrand: read 1 (or a single-end read) has the transcript's sequence, and read 2 is its reverse complement.

Notes

  • A strand tag written by the aligner takes priority over these flags: XS (HISAT2; STAR with --outSAMstrandField intronMotif) or minimap2's ts. The flags decide the strand only for records without such a tag, which are mostly unspliced reads.
  • --fr and --rf can't be used together.
  • For long reads (--lr, --lr-hq) both flags and strand tags are ignored, and both strands are always tried.
