Short reads, start to finish

Align short reads to the genome, project them with bramble, and quantify with salmon.

This guide expands the Quick start into a complete short-read analysis. It runs on the small example data that comes with bramble, so every step finishes in seconds; after each step, a note says what to change for your own data.

What you need

  • bramble (see Installation), STAR (or HISAT2), samtools, gffread, and salmon.
  • About 2 GB of memory for the example. A full human genome needs about 32 GB for STAR.

Get the example data

git clone https://github.com/zrudnick/bramble.git
cd bramble/example

# the genome: chr22 of hg38, from UCSC
curl -LO https://hgdownload.soe.ucsc.edu/goldenPath/hg38/chromosomes/chr22.fa.gz
gunzip chr22.fa.gz chess2.2_chr22.gtf.gz

short_reads.fq.gz holds about 100,000 simulated single-end reads of 101 bases from chr22 transcripts, from a forward-stranded library: each read has the sequence of its transcript. chess2.2_chr22.gtf is the annotation they were simulated from.

1. Build the aligner index

STAR --runMode genomeGenerate --runThreadN 4 --genomeDir star_index \
     --genomeFastaFiles chr22.fa --sjdbGTFfile chess2.2_chr22.gtf \
     --sjdbOverhang 100 --genomeSAindexNbases 11

Building the index with the annotation (--sjdbGTFfile) makes STAR prefer annotated exon boundaries, which is exactly where bramble looks for them.

Your data: use your genome and annotation, with the same chromosome names in both. Set --sjdbOverhang to your read length minus one, and leave out --genomeSAindexNbases 11, which is only for small genomes like this one chromosome. With HISAT2, build the index with the annotation's splice sites and exons:

hisat2_extract_splice_sites.py annotation.gtf > splice_sites.txt
hisat2_extract_exons.py annotation.gtf > exons.txt
hisat2-build -p 8 --ss splice_sites.txt --exon exons.txt genome.fa hisat2_index

2. Align to the genome

STAR --runThreadN 4 --genomeDir star_index \
     --readFilesIn short_reads.fq.gz --readFilesCommand zcat \
     --outSAMtype BAM Unsorted --outSAMstrandField intronMotif \
     --outFileNamePrefix short.

This writes short.Aligned.out.bam. Ask for unsorted output: it keeps each read's alignments together, which is what bramble needs. --outSAMstrandField intronMotif adds the XS strand tag to spliced reads, which bramble uses to skip transcripts on the wrong strand.

Your data: for paired-end reads give both files, --readFilesIn reads_1.fq.gz reads_2.fq.gz. Keep the secondary alignments that STAR reports for reads that align to several places (up to 10 by default): bramble projects each of them, and the quantifier decides between them. With HISAT2: hisat2 -p 8 -x hisat2_index -1 reads_1.fq.gz -2 reads_2.fq.gz | samtools view -b -o sample.bam -. If you only have a coordinate-sorted BAM, collate it first: samtools collate -o sample.collated.bam sample.sorted.bam.

3. Project with bramble

bramble short.Aligned.out.bam -G chess2.2_chr22.gtf -o short.transcriptome.bam --fr -p 4

The default preset is for short reads, so the only option needed is the strandedness: these reads have the sequence of their transcript, so the library is --fr. bramble finishes in a few seconds and reports what it did; nearly all of the 99,776 aligned reads project, onto about 10 transcripts each on average.

Your data: use the same annotation you gave the aligner. Most stranded kits (dUTP-based, such as Illumina TruSeq Stranded) need --rf; leave both flags out for an unstranded library. See Strandedness.

4. Build the transcript sequences

gffread -w transcripts.fa -g chr22.fa chess2.2_chr22.gtf

salmon needs the sequence of every transcript, named as in bramble's output. gffread names each sequence by its transcript ID, so the names match.

Your data: build the sequences from the same annotation. Avoid transcript FASTA files whose headers pack several fields into the name, such as GENCODE's |-separated headers, unless you trim them to the transcript ID.

5. Quantify with salmon

salmon quant -t transcripts.fa -l SF -a short.transcriptome.bam -o short_salmon -p 4

-l SF is salmon's name for single-end reads from a forward-stranded library. Estimated read counts and TPM per transcript are in short_salmon/quant.sf: 

Name           Length  EffectiveLength  TPM            NumReads
CHS.35786.5    719     469.000          238722.430735  5542.565
CHS.36093.10   6541    6291.000         10530.548681   3279.559
CHS.35882.18   1161    911.000          63162.728320   2848.551

Your data: -l A lets salmon detect the library type, or give it yourself (ISR for paired-end dUTP, IU for paired-end unstranded).

Don't sort bramble's output. salmon expects the two mates of a pair next to each other; sorting separates them.

Look at the result

Each read end has exactly one primary record in bramble's output, so counting primary records gives the number of read ends that projected. Compare it with the genome BAM: 

samtools view -c -F 0x904 short.Aligned.out.bam        # aligned: 99776
samtools view -c -F 0x904 short.transcriptome.bam      # projected: 99762

And to see how many transcripts each read fits (its NH tag):

samtools view -F 0x904 short.transcriptome.bam | grep -o 'NH:i:[0-9]*' | sort | uniq -c | sort -k1,1nr | head

In the example nearly every read projects, because the reads were simulated from the annotation. In real data, reads from introns, intergenic regions, and transcripts missing from the annotation don't project, so expect a lower fraction; how much lower depends on the sample and on how complete the annotation is.
