Sample-specific annotations with StringTie

Assemble transcripts from your own reads, add them to the annotation, then project.

bramble only projects reads onto annotated transcripts, so transcripts your samples express but the annotation lacks get no reads. One way to add them is to assemble transcripts from the reads with StringTie, guided by the reference annotation, and project onto the result. This guide walks through it on the example short reads; the bramble paper suggests this approach but has not benchmarked it.

What you need

  • Everything from the short-read guide, plus StringTie and gffcompare.
  • The STAR alignment from that guide, short.Aligned.out.bam, in the example folder.

1. Sort a copy for StringTie

samtools sort -o short.sorted.bam short.Aligned.out.bam

StringTie needs alignments sorted by coordinate, but bramble needs each read's records together. Keep both: the sorted copy for StringTie, the unsorted original for bramble.

2. Assemble transcripts

stringtie short.sorted.bam -G chess2.2_chr22.gtf --fr -p 4 -o short.stringtie.gtf

-G guides the assembly with the reference annotation, so known transcripts keep their IDs. --fr is the strandedness, with the same meaning as in bramble.

Your data: assemble each sample separately. For long reads, add -L.

3. Merge into one annotation

stringtie --merge -G chess2.2_chr22.gtf -o merged.gtf short.stringtie.gtf

The merged annotation contains the reference transcripts plus the new ones, which StringTie names MSTRG.*. In the example, it holds the 7,071 reference transcripts and 40 new ones.

Your data: merge all samples at once (stringtie --merge -G annotation.gtf -o merged.gtf sample1.gtf sample2.gtf ...) and use the merged annotation for every sample, so their quantities are comparable. stringtie --merge also has options to leave out lowly expressed transcripts; see stringtie --help.

4. See what is new

gffcompare -r chess2.2_chr22.gtf -o cmp merged.gtf

cmp.stats summarizes how the merged annotation compares with the reference, and cmp.merged.gtf.tmap gives each transcript a class code: = for an exact match to a reference transcript, j for a new isoform that shares a splice junction with one, u for a new gene, and so on. In the example, 7,069 transcripts match the reference exactly and most of the new ones are class j.

5. Project and quantify

bramble short.Aligned.out.bam -G merged.gtf -o merged.transcriptome.bam --fr -p 4
gffread -w merged.fa -g chr22.fa merged.gtf
salmon quant -t merged.fa -l SF -a merged.transcriptome.bam -o merged_salmon -p 4

From here on it is the same as the short-read guide, with the merged annotation in place of the reference: bramble projects onto the new transcripts too, and they appear in merged_salmon/quant.sf under their MSTRG names.

Caveats

  • Assembly errors become annotation errors. An assembled transcript that doesn't exist can take reads from real ones. In the example, every read was simulated from a reference transcript, yet the 40 assembled transcripts take about 4,500 of the 100,000 reads. Filtering lowly expressed transcripts when merging, and checking the new ones with gffcompare, keeps this in check.
  • Use one merged annotation for all samples, so every sample is quantified against the same set of transcripts.
