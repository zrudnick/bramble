Troubleshooting

Common problems, how to recognize them, and how to fix them.

Few or no reads project

Compare the number of reads aligned with the number projected:

samtools view -c -F 0x904 genome.bam            # aligned reads
samtools view -c -F 0x904 transcriptome.bam     # projected reads

If the second number is much lower than you expect, check these, in order:

  • Chromosome names. The BAM and the annotation must name chromosomes the same way (chr1 in both, or 1 in both). Compare samtools view -H genome.bam | grep '^@SQ' | head -3 with grep -v '^#' annotation.gtf | cut -f1 | sort -u | head -3. See Existing genome BAMs for how to rename.
  • Genome build. The annotation must be for the genome the reads were aligned to. In the BAM header, chr1 is 248,956,422 bases long in hg38 and 249,250,621 in hg19.
  • Strand flag. With the wrong --fr/--rf, most unspliced short reads don't project. Try the other flag, or none; see Stranded libraries.
  • Preset. Long reads need --lr-hq or --lr; with the short-read default, few of them fit exactly. See Choosing a preset.
  • Annotation coverage. A long read only projects if its whole exon chain matches an annotated transcript. If your sample expresses many transcripts the annotation lacks, many long reads won't project; a more complete annotation helps. See Incomplete annotations.

The output looks wrong

Several primary alignments for one read, wrong NH, or mates not paired usually mean the input wasn't grouped by read name. bramble treats each run of consecutive records with the same name as one read; if a read's records are scattered (as in a coordinate-sorted BAM), each piece is handled as a separate read. To check, this prints names that appear in more than one place: 

samtools view genome.bam | cut -f1 | uniq | sort | uniq -d | head

If it prints anything, collate the BAM first: samtools collate -o genome.collated.bam genome.bam.

The quantifier complains

  • Transcript names don't match. The quantifier's transcript sequences must be named exactly as in bramble's output (the annotation's transcript IDs). Build them from the same annotation with gffread -w transcripts.fa -g genome.fa annotation.gtf.
  • salmon warns about mates. The output was probably sorted. salmon expects the two mates of a pair next to each other, which is how bramble writes them; use bramble's output as it is.
  • oarfish rejects the file. oarfish does not accept coordinate-sorted BAMs; again, use bramble's output as it is.

Looking at one read

To see what bramble did with a particular read, pull its records from both files:

samtools view genome.bam | awk '$1 == "READ_NAME"'
samtools view transcriptome.bam | awk '$1 == "READ_NAME"'

Each output record is one placement on one transcript; NH is the number of placements of that read end, mates share the same HI, and exactly one record per read end is primary. See Transcriptome BAM.

Reporting a problem

Please open an issue with the bramble version (bramble -V), the exact command, and, if you can, a small BAM that shows the problem. The records of one read are often enough: 

samtools view -h genome.bam | awk '/^@/ || $1 == "READ_NAME"' | samtools view -b -o example.bam -
