Single-cell and UMI data

Projecting single-cell alignments, with their cell barcodes and UMIs.

bramble has no single-cell-specific features, but it works on single-cell data: it projects each alignment on its own, whatever cell it came from, and keeps the barcode and UMI tags. Cell demultiplexing, UMI deduplication, and per-cell counting happen downstream, in tools that read those tags.

What is kept

Every projected record keeps these tags from its genome alignment:

  • cell barcodes and UMIs: CB CR CY UB UR UY, and also BC QT MI OX BZ RX QX BX;
  • the read group (RG), with its @RG header line.

So a read's barcode and UMI are on all of its projected records, one per transcript it fits. See Transcriptome BAM for the full list of tags.

Running bramble

  • Use the BAM from your single-cell aligner, with the barcode tags in it. These BAMs are often sorted by coordinate; collate them first (samtools collate -o genome.collated.bam genome.bam).
  • Choose the preset from the technology, as for bulk data: the default for short reads, --lr-hq for PacBio, --lr for Nanopore, with -S for long reads. See Choosing a preset.
  • For short-read protocols that read the transcript from one end, set the strand flag; see Stranded libraries.

After bramble

The output is a transcriptome BAM with barcodes and UMIs, so any tool that quantifies transcripts from such a BAM per cell can use it. To quantify a group of cells together (pseudobulk), for example one cell type, select its cells by barcode and quantify the result like bulk data: 

# cells.txt: one barcode per line, as in the CB tag
samtools view -b -D CB:cells.txt -o celltype.transcriptome.bam transcriptome.bam

Each read keeps all of its records in the selected file, so the output can go straight to salmon or oarfish.
