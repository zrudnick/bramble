Long reads, start to finish

Align PacBio or Oxford Nanopore reads to the genome, project them with bramble, and quantify with oarfish.

This guide expands the Quick start into a complete long-read analysis. It runs on the small example data that comes with bramble, which has both PacBio and Oxford Nanopore (ONT) reads; after each step, a note says what to change for your own data.

What you need

  • bramble (see Installation), minimap2 (with its paftools.js script, which needs k8), samtools, and oarfish.

Get the example data

git clone https://github.com/zrudnick/bramble.git
cd bramble/example

# the genome: chr22 of hg38, from UCSC
curl -LO https://hgdownload.soe.ucsc.edu/goldenPath/hg38/chromosomes/chr22.fa.gz
gunzip chr22.fa.gz chess2.2_chr22.gtf.gz

pacbio_reads.fa.gz and ont_reads.fq.gz hold about 5,000 simulated reads each from chr22 transcripts. chess2.2_chr22.gtf is the annotation they were simulated from.

1. Annotated splice junctions for minimap2

paftools.js gff2bed chess2.2_chr22.gtf > junctions.bed

Given the annotation's junctions (--junc-bed below), minimap2 prefers annotated splice sites, which is exactly where bramble looks for exon boundaries.

2. Align to the genome

# PacBio
minimap2 -t 4 -ax splice:hq --junc-bed junctions.bed chr22.fa pacbio_reads.fa.gz \
  | samtools view -b -o pacbio.genome.bam -

# ONT
minimap2 -t 4 -ax splice --junc-bed junctions.bed chr22.fa ont_reads.fq.gz \
  | samtools view -b -o ont.genome.bam -

splice:hq is minimap2's preset for accurate long reads such as PacBio HiFi; splice is for noisier reads such as ONT. minimap2's output keeps each read's alignments together, so it goes straight to bramble without sorting.

Your data: use your genome and annotation, with the same chromosome names in both. For a large genome, build minimap2's index once (minimap2 -x splice:hq -d genome.mmi genome.fa) and pass genome.mmi in place of the FASTA. If you only have a coordinate-sorted BAM, collate it first: samtools collate -o sample.collated.bam sample.sorted.bam.

3. Project with bramble

# PacBio
bramble pacbio.genome.bam -G chess2.2_chr22.gtf -S chr22.fa -o pacbio.transcriptome.bam --lr-hq -p 4

# ONT
bramble ont.genome.bam -G chess2.2_chr22.gtf -S chr22.fa -o ont.transcriptome.bam --lr -p 4

--lr-hq and --lr are the presets for accurate and noisier long reads: they set how far a read's exon boundaries may be from the annotation, and turn on scoring by similarity. -S gives the genome sequence, which bramble uses to rescue soft-clipped read ends. Each run takes a second or two.

The two presets show up in the result. Under --lr-hq, 61% of the PacBio reads fit exactly one transcript; under the more tolerant --lr, 35% of the ONT reads do, and the rest fit several. The quantifier sorts out those ambiguous reads using the alignment scores bramble writes (AS).

Your data: use --lr-hq for PacBio and --lr for ONT, with the same annotation you gave minimap2. See Read-type presets for what each changes. Always give -S with the genome FASTA you aligned to: clip rescue makes quantification more accurate, and without it, read ends the aligner soft clipped stay clipped.

4. Quantify with oarfish

oarfish -j 4 -a pacbio.transcriptome.bam -o pacbio --filter-group no-filters --model-coverage
oarfish -j 4 -a ont.transcriptome.bam -o ont --filter-group no-filters --model-coverage

--filter-group no-filters turns off oarfish's alignment filters, which are tuned for minimap2's transcriptome alignments; bramble has already decided which transcripts each read fits. --model-coverage turns on oarfish's model of read coverage along each transcript. Estimated read counts per transcript are in pacbio.quant: 

tname          len   num_reads
CHS.35882.9    2357  1254.99
CHS.35786.6    552   530.76
CHS.35829.5    1086  438.94

TranSigner also reads bramble's output; the bramble paper ran it with --keep-low --use-psw.

Don't sort bramble's output. oarfish does not accept coordinate-sorted input.

Look at the result

Each read has exactly one primary record in bramble's output, so counting primary records gives the number of reads that projected. Compare it with the genome BAM: 

samtools view -c -F 0x904 pacbio.genome.bam          # aligned: 4981
samtools view -c -F 0x904 pacbio.transcriptome.bam   # projected: 4980

And to see how many transcripts each read fits (its NH tag):

samtools view -F 0x904 pacbio.transcriptome.bam | grep -o 'NH:i:[0-9]*' | sort | uniq -c | sort -k1,1nr | head

In the example nearly every read projects, because the reads were simulated from the annotation. A long read only projects if its whole exon chain matches a transcript, so with real data, reads from transcripts missing from the annotation don't project. Expect a lower fraction than for short reads, depending on how complete the annotation is.
