Choosing a preset and tuning tolerances

Which preset fits your data, and when to change its settings.

Choosing a preset

DataPreset
Illumina and other short readsdefault (no option)
PacBio HiFi (including Kinnex and Revio)--lr-hq
Oxford Nanopore--lr

For other long-read data, choose by accuracy: --lr-hq for reads that are about as accurate as PacBio HiFi, --lr for anything noisier, such as older PacBio CLR reads. For recent, more accurate Nanopore chemistries, try both on a sample and compare (see below). The Read-type presets page lists every value each preset sets.

What the tolerances trade off

Every tolerance trades the same two things. A wider tolerance keeps reads whose exon boundaries the aligner put a few bases off, which is common for noisy long reads; but it also lets a read fit more transcripts, including ones it didn't come from, so more reads end up ambiguous. A narrower tolerance makes each placement more certain, at the cost of dropping reads.

  • --max-junction-insertion and --max-junction-deletion: how far a read's exon may run past, or stop short of, an annotated splice site.
  • --max-soft-clip: how far the read's two ends may reach past the transcript's exons.
  • --max-error-exon: the longest short exon that may be missing from the read, or extra in it, as a sequencing error.
  • --similarity-threshold: how closely the projected alignment must match the transcript, for long reads.

In bramble's example data, this shows up directly: under --lr-hq, 61% of the PacBio reads fit exactly one transcript; under the more tolerant --lr, 35% of the Nanopore reads do.

Measuring the effect on your data

Run bramble on a sample with each setting you are considering, and compare two numbers: how many reads project, and how many transcripts each read fits. 

samtools view -c -F 0x904 genome.bam            # aligned reads
samtools view -c -F 0x904 transcriptome.bam     # projected reads
samtools view -F 0x904 transcriptome.bam | grep -o 'NH:i:[0-9]*' | sort | uniq -c | sort -k1,1nr | head

If a looser setting projects many more reads, the stricter one was dropping reads that the aligner placed slightly off. If it projects about the same number but each read fits more transcripts, the looser setting only adds ambiguity, and the stricter one is the better choice.

Changing one setting

Any option you give overrides the preset, and the rest of the preset stays as it is. For example, to keep --lr but allow longer soft clips: 

bramble genome.bam -G annotation.gtf -S genome.fa -o transcriptome.bam --lr --max-soft-clip 100

When to use --strict

--strict requires every exon boundary of a read to match the annotation exactly and turns the similarity filter off. Use it when you want only placements that agree perfectly with the annotation, for example to study reads that support a transcript's exact structure, and are willing to lose reads the aligner placed slightly off. Added to --lr or --lr-hq, it keeps their long-read behaviour.
